# 五子棋 · Gomoku

一个完整可玩的五子棋游戏，部署在 Cloudflare Workers 上：强 AI 人机对战、同屏双人对战、房间号在线联机对战。

## 玩法

- **人机对战**：4 档难度（简单 / 普通 / 困难 / 大师），可选执黑（先行）或执白
- **双人对战**：同一台设备轮流落子
- **在线对战**：创建房间把房间号发给朋友，对方输入即可加入；开局随机决定黑白（1.5 秒揭晓，服务端拦截提前落子），之后每局轮换先手；支持悔棋 / 重开 / 和棋协商与认输
- 规则：15×15 棋盘，黑棋先行，横 / 竖 / 斜任意连成五子获胜，无禁手
- 附带：落子提示、棋谱记录、对局计时、音效与震动、人机战绩统计（本机保存）

## AI 设计

AI 引擎位于 `src/engine.js` 的 `ENGINE_JS`（纯逻辑，可在浏览器与 Node 中运行）：

1. **棋型评估**：连子数 × 开放端计分，识别活四 / 冲四 / 活三 / 眠三等棋型，并识别「跳一格」断点棋型（如 `XX_X`）；方向棋型走查表判型并随落子增量维护
2. **组合威胁**：单点评估阶段直接识别双四、四三、双三等必杀组合并给予高额加分——进攻能造杀，防守会抢占对方的组合点
3. **全盘评估**：5 格窗口势能 + 连子段聚合 + 最大威胁三部分全部增量维护，叶子评估 O(1)；防守方威胁加权（攻防兼备），带评估缓存
4. **搜索**：Negamax + Alpha-Beta 剪枝 + PVS + Zobrist 置换表（跨手保留，杀棋分按层归一化）+ killer / history 着法排序；迭代加深并设单步时间上限
5. **VCF 求解器（大师）**：连续冲四杀链精确求解（三态语义：必胜 / 已证无 / 预算中止，绝不把未算完当无杀）；有杀直接兑现，对方有杀则根节点只走已验证的安全着法
6. **双活三攻防校验（大师）**：搜索对「下一步成双活三」定价不足，故根节点再用精确棋型判据兜底——自己能先成双活三且对方无即时四 / 五点 / VCF 威胁时抢先成形（同成先成者胜），对方能成而搜索着法未防住时改选已验证的防法；是否收手只看落子棋型、不看搜索分数（分数会因组合评估膨胀而虚报必胜）。专项实测（同一批 40 道防守题，未加校验的引擎仅处理 6/40、白棋防守 1/20；加校验后 40/40 全处理、白棋防守 19/20；进攻识别 22/24 不变）
7. **造双线四点攻防校验（大师）**：一手同时造出分布在两条线上的活四点（如断点三交汇）与双活三同级必杀，但 VCF 只认以四开局的杀链、双活三校验只数连续子，均覆盖不到，故根节点用窗口棋型兜底——按「方向 + 线号」枚举活四点及其造点手：自己能抢造且对方无即时威胁时先造，对方能造而搜索着法未破坏时改选已验证的破坏点（占交汇点 / 四点 / 活四端点），造四反制有豁免；破坏点须模拟验证造点与双活三同时清空，且对方有双活三在手时不抢造（裁决权归双活三校验）。专项实测（10 道造点防守题：未加校验 5/10，加校验后 10/10；冻结题库 16 题全过，双活三回归 20/20 不受影响）
8. **强制着法裁剪**：对方存在成五点时，候选只保留堵点（除非自己能立即成五）
9. **难度分级**：简单带概率性次优着法模拟真人失误，但不会漏堵成五；普通 4 层、困难 5 层、大师 6 层（单步上限 2.8 秒，平均约 1.4 秒）

## 移动端体验

- 棋盘按屏幕宽度自适应 + 设备像素比（DPR）高清渲染
- 触摸落子采用「按下预览 → 拖动微调 → 松手落子」，避免手指遮挡误触
- 底部拇指区工具栏、底部弹层菜单、安全区适配、棋盘坐标标注

## 本地开发与测试

```bash
npm run dev     # wrangler dev 本地运行
npm test        # AI 仿真测试：战术题 + 陪练对局 + 性能（node tests/ai.test.mjs，13 项）
npm run test:ui # UI 功能仿真：jsdom 驱动完整对弈链路（需先 npm install，15 项）
npm run deploy  # 部署到 Cloudflare Workers
node tests/vcf.test.mjs       # VCF 求解器专项（10 项）
node tests/integrity.test.mjs # 搜索状态完整性（幻影子防护）
node tests/evalinc.test.mjs   # 增量评估与全量评估等价性
node tests/d3guard.test.mjs   # 双活三识别率回归（冻结题库 20 防守 + 12 进攻）
node tests/crtguard.test.mjs  # 造双线四点识别率回归（冻结题库 10 防守 + 4 进攻 + 抢造 / 反制）
```

## 结构

- `src/index.js`：Worker 入口 + Durable Object 联机房间（`GameRoom`，状态持久化、12 小时无人活动自动清理）。注意：入口模块只能导出 handler 与 DO 类——workerd 会拒绝字符串等其它类型的顶层导出并导致整个 Worker 启动失败，因此引擎与页面拆为独立模块由入口 import
- `src/engine.js`：AI 引擎源码（`ENGINE_JS`）
- `src/page.js`：前端页面（内嵌引擎与全部 UI 逻辑）
- `tests/ai.test.mjs`：AI 引擎 Node 仿真测试（13 项）
- `tests/ui.test.mjs`：UI 功能仿真（jsdom，15 项）
- `tests/ws.test.mjs`：联机协议端到端测试（14 项；需先 `npx wrangler dev --port 8787 --local` 再 `npm run test:ws`）
- `tests/room.test.mjs`：房间状态恢复与过期清理测试（38 项；模拟 Durable Object 休眠重建后从 storage + 存活连接恢复会话与棋谱，防「后进者被误判为房主」；含随机抽签/轮换先手、揭晓前拦截、闹钟节流与棋谱紧凑编码往返、旧格式/旧连接兼容）
- `tests/vcf.test.mjs` / `tests/integrity.test.mjs` / `tests/evalinc.test.mjs`：VCF 求解器专项、搜索状态完整性（防求解器污染棋盘）、增量评估等价性校验
- `tests/d3guard.test.mjs` + `tests/d3-positions.json`：双活三识别率常驻回归（冻结题库，防识别能力退化）
- `tests/crtguard.test.mjs` + `tests/crt-positions.json`：造双线四点识别率常驻回归（冻结题库，判据为与引擎实现无关的暴力窗口法）
- `tests/load.mjs`：多房间对战压测（机器人互打，统计手数/局数/错误，用于推演额度消耗）
- 推送到 `main` 后由 GitHub Actions 自动部署（`.github/workflows/deploy.yml`）
